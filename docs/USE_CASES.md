# Сценарии использования (Use Cases)

## Веб-мессенджер

## UC-01. Создание группового чата

**Актор:** Пользователь

**Предусловие:** Пользователь авторизован.

**Результат:** Создан групповой чат, пользователь назначен его администратором.

### Основной сценарий

1. Пользователь нажимает кнопку создания группового чата.
2. Система открывает форму создания группы.
3. Пользователь вводит название группы.
4. Пользователь подтверждает создание.
5. Система создаёт групповой чат и назначает пользователя администратором.
6. Система открывает созданный чат.

### Альтернативные сценарии

- **А1.** Пользователь не указал название группы — система не позволяет создать чат.
- **А2.** При создании произошла ошибка — система сообщает об ошибке, пользователь может повторить попытку.

## UC-02. Отправка сообщения

**Актор:** Пользователь

**Предусловие:** Пользователь авторизован и имеет доступ к выбранному чату.

**Результат:** Сообщение сохранено на сервере и доступно участникам чата.

### Основной сценарий

1. Пользователь открывает чат.
2. Пользователь вводит текст сообщения и нажимает кнопку отправки.
3. Клиент отправляет сообщение на сервер через WebSocket.
4. Сервер проверяет, имеет ли пользователь доступ к чату.
5. Сервер сохраняет сообщение в базе данных.
6. Сервер отправляет отправителю подтверждение сохранения.
7. Сообщение отображается в чате и передаётся другим подключённым участникам.

### Альтернативные сценарии

- **А1.** Сообщение пустое — отправка не выполняется.
- **А2.** Пользователь потерял доступ к чату — сервер отклоняет отправку.
- **А3.** Соединение с сервером прервано — сообщение остаётся неподтверждённым, пользователь может повторить отправку.
- **А4.** Получатель не в сети — сообщение сохраняется и будет доступно ему после подключения.

## UC-03. Исключение участника из группы

**Актор:** Администратор группы

**Предусловие:** Администратор авторизован, выбранный пользователь состоит в группе.

**Результат:** Пользователь исключён из группы и больше не имеет доступа к её сообщениям.

### Основной сценарий

1. Администратор открывает групповой чат.
2. Администратор открывает список участников.
3. Администратор выбирает участника для исключения.
4. Администратор подтверждает исключение.
5. Сервер проверяет права администратора.
6. Система удаляет пользователя из участников группы.
7. У исключённого пользователя чат пропадает из списка, доступ к истории закрывается.
8. У остальных участников чат и история сообщений сохраняются.

### Альтернативные сценарии

- **А1.** Пользователь уже не состоит в группе — система сообщает об этом.
- **А2.** У пользователя нет прав администратора — исключение не выполняется.
- **А3.** Исключённого пользователя снова приглашают — он получает доступ только к сообщениям с момента повторного вступления.
