# Спецификация требований к ПО

## Веб-мессенджер

**Версия:** 1.0

## 1. Описание проекта

Веб-мессенджер для общения пользователей в личных и групповых чатах.

Основные возможности: регистрация и вход, обмен сообщениями в реальном времени, хранение истории, поиск сообщений, управление участниками групп и уведомления.

## 2. Роли пользователей

- **Гость** — может зарегистрироваться или войти в аккаунт.
- **Пользователь** — может создавать чаты, отправлять и читать сообщения.
- **Администратор группы** — может добавлять и удалять участников своей группы.

## 3. Функциональные требования

### 3.1. Авторизация

- FR-01. Регистрация и вход в аккаунт.
- FR-02. Авторизация через JWT.
- FR-03. Доступ к чатам только после входа в аккаунт.

### 3.2. Чаты

- FR-04. Создание личного чата с другим пользователем.
- FR-05. Если личный чат уже существует, открывается он, а новый не создаётся.
- FR-06. Создание группового чата с названием.
- FR-07. Добавление и удаление участников группы администратором.
- FR-08. Возможность самостоятельно выйти из группы.
- FR-09. Просмотр списка своих чатов.

### 3.3. Сообщения

- FR-10. Отправка и получение сообщений через WebSocket в реальном времени.
- FR-11. Хранение сообщений в базе данных.
- FR-12. Подтверждение от сервера после сохранения сообщения.
- FR-13. Загрузка истории сообщений частями при прокрутке вверх.
- FR-14. Поиск сообщений по тексту внутри чата.

### 3.4. Уведомления

- FR-15. Всплывающие уведомления о новых сообщениях внутри приложения.
- FR-16. Счётчик непросмотренных сообщений рядом с каждым чатом.
- FR-17. Уведомление о добавлении в группу.
- FR-18. Возможность отключить всплывающие уведомления для отдельного чата. Счётчик сообщений при этом продолжает работать.

## 4. Бизнес-правила

- BR-01. Между двумя пользователями может быть только один личный чат.
- BR-02. Создатель группы автоматически становится её администратором.
- BR-03. Если администратор выходит из группы, новым администратором становится первый приглашённый из оставшихся участников.
- BR-04. Если из группы выходит последний участник, группа удаляется.
- BR-05. После исключения из группы пользователь больше не видит этот чат и его сообщения.
- BR-06. Если пользователя снова добавили в группу, он видит только новые сообщения с момента возвращения.
- BR-07. Сообщение считается доставленным на сервер, когда оно сохранено и сервер отправил подтверждение.
- BR-08. Читать и отправлять сообщения могут только участники чата с доступом к соответствующей переписке.

## 5. Нефункциональные требования

- NFR-01. Пароли не должны храниться в базе данных в открытом виде.
- NFR-02. Сервер должен проверять, есть ли у пользователя доступ к нужному чату.
- NFR-03. При потере соединения уже сохранённые сообщения не должны пропадать.
- NFR-04. Новые сообщения должны появляться без перезагрузки страницы.

## 6. Что не входит в MVP

В первой версии не планируем делать:

- Аудио- и видеозвонки.
- Отправку файлов и изображений.
- Реакции на сообщения.
- Редактирование и удаление сообщений.
- Статусы прочтения.
- Push-уведомления браузера.
- Отдельную систему модерации.
- LLM-суммаризацию переписки.
